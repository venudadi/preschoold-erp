# System Architecture & Documentation - prodv1_231225

**Date:** December 23, 2025
**Version:** 1.0 (Production Candidate)

## 1. Project Overview
The Vanisris Preschool ERP is a comprehensive management system built with a **Node.js/Express** backend and **MySQL** database. It manages core preschool operations including student enrollment, attendance, financial management, and academic lesson planning.

## 2. Backend Architecture
The backend follows a modular, route-centric architecture.

- **Entry Point:** `backend/index.js` initializes the Express app, database connection pool, and mounts API routes.
- **Database:** Uses `mysql2` with a connection pool (`backend/db.js`).
- **Authentication:** JWT-based authentication with role-based access control (RBAC). Middleware: `backend/authMiddleware.js`.
- **Environment:** Configuration via `.env` files (staging/production).

### Key Directories
- `backend/controllers/`: Complex business logic (e.g., expenses, portfolio).
- `backend/routes/`: Route definitions (e.g., `lessonPlanRoutes.js`).
- `backend/middleware/`: Authentication and request processing.
- `backend/services/`: External integrations (Email, Claude API).

## 3. Lesson Planning Module
A critical component handling the academic workflow from creation to execution and feedback.

### Workflow
1.  **Academic Coordinator:** Creates weekly lesson plans for individual children or entire classrooms.
    *   *Endpoint:* `POST /api/lesson-plans/coordinator/create`
2.  **Admin / Center Director:** Reviews submitted plans and forwards them to specific teachers.
    *   *Endpoint:* `POST /api/lesson-plans/admin/:id/forward-to-teacher`
3.  **Teacher:** Receives assignments, acknowledges them, executes activities, and submits feedback.
    *   *Endpoint:* `POST /api/lesson-plans/teacher/:id/feedback`
4.  **Feedback Loop:** Completed plans with feedback are returned to the coordinator for review.

### Database Schema (Lesson Planning)
The module uses a set of relational tables (Collation: `utf8mb4_0900_ai_ci`):

*   **`lesson_plans`**: Core table. Stores week dates, objectives, status (`draft`, `submitted`, `in_progress`, `completed`), and links to `child_id` or `classroom_id`.
*   **`lesson_plan_activities`**: Detailed activities for each plan (Category, Day, Materials, Instructions).
*   **`lesson_plan_assignments`**: Links a lesson plan to a specific `teacher_id`.
*   **`lesson_plan_feedback`**: Stores teacher observations, child engagement levels, and ratings.
*   **`lesson_plan_workflow`**: Audit trail recording every status change and action (who did what, when).

## 4. Recent Critical Fixes (Dec 2025)

### Database Collation
*   **Issue:** `Illegal mix of collations` error between existing tables (`utf8mb4_0900_ai_ci`) and newly created lesson plan tables (`utf8mb4_unicode_ci`).
*   **Resolution:** Converted `lesson_plan_activities`, `lesson_plan_feedback`, `lesson_plan_assignments`, and `lesson_plan_workflow` to `utf8mb4_0900_ai_ci`.

### Schema Corrections
*   **Issue:** `Unknown column 'c.admission_date'` error in Academic Coordinator queries.
*   **Resolution:** Removed the invalid `admission_date` column reference from the `children` query in `backend/lessonPlanRoutes.js`.
